# Append-Only Audit Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task by task. Steps use checkbox syntax for tracking.

**Goal:** Persist minimal, idempotent audit records for sensitive payments, role projections, account deletion, and webhook signature failures, with immutable PostgreSQL storage and two-year retention.

**Architecture:** Add a PostgreSQL `AuditLog` model and an `AuditLogService` that accepts only append operations. Write required audit rows in the same PostgreSQL transaction as payment/refund events; append before Mongo role/deletion mutations. A database trigger blocks row mutation, and a restricted security-definer function performs the two-year cleanup.

**Tech Stack:** NestJS, Prisma PostgreSQL client, PostgreSQL PL/pgSQL, Vitest, Podman-backed integration tests.

**Spec:** `docs/superpowers/specs/2026-11-04-audit-log-design.md`

## Global Constraints

- Keep audit details minimal and allow-listed; never store raw webhook bodies, signatures, credentials, or direct contact data.
- Keep records independent of user/payment foreign keys so deletion cannot erase history.
- Do not add audit read APIs or enable PostgreSQL RLS in this feature.
- Security failure audit writes are best-effort; mutation/payment audit writes must persist before their corresponding external or Mongo side effect.

## Review Focus

- Duplicate service retries create only one audit event for the same provider/refund event key — unit tests and PostgreSQL unique-index test.
- API/worker roles cannot update, delete, or truncate audit rows — isolated PostgreSQL privilege/trigger tests.
- Cleanup deletes only rows older than two years — isolated PostgreSQL cutoff test.
- Audit persistence failure does not proceed with required account/role/payment mutation — unit tests.
- Webhook rejection audit does not persist attacker-controlled headers/body and does not replace the original 400 response — controller/service tests.

`AuditLogService.append(input, transaction?)` accepts a typed `AuditLogInput`, writes once by optional unique `eventKey`, and ignores only a duplicate-key error. `recordSecurityFailure(provider, route)` is the best-effort wrapper for public webhook rejection paths. `AuditLogRetentionScheduler.cleanup()` calls the no-argument `prepai_prune_audit_log()` database function.
